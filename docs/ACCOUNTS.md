# Аккаунты LEXI

## Где находятся данные

Словарь остается в `data/*.json`. Личные данные находятся в SQL-базе: таблица `users` хранит уникальные email/логин, scrypt-хеш, фото, учебное состояние и его версию. Таблица `auth_rate_buckets` ограничивает попытки регистрации и входа между worker-процессами. Пароли и сессионные/CSRF-токены не записываются в localStorage.

SQLite создается автоматически в `instance/lexi.sqlite3`. PostgreSQL подключается через `DATABASE_URL` (поддерживаются `postgres://` и `postgresql://`, драйвер psycopg). Таблицы создаются при запуске; одновременный запуск worker-процессов сериализован блокировкой. Проверка подключения: `python -m flask --app app init-db`. Последующие изменения схемы потребуют отдельной миграции: `create_all` не изменяет существующие столбцы. Текущая версия добавляет таблицу маркеров `data_migrations` и однократную миграцию учебных данных, описанную ниже.

Локальный постоянный ключ подписи создается в `instance/.session-key`. На сервере задайте постоянный случайный `SECRET_KEY` через Environment, а также `LEXI_COOKIE_SECURE=1` для HTTPS. `LEXI_TRUST_PROXY=1` разрешается только за одним доверенным reverse proxy, как на Render. Без прокси оставьте его выключенным, чтобы адрес клиента для ограничения входа нельзя было подделать через HTTP-заголовок.

## Вход и гостевой просмотр

Новый посетитель сначала видит отдельный экран регистрации с формой по центру и переключателем трех оформлений. **Sign in** открывает вход для существующего аккаунта. **Continue as guest** начинает временный просмотр без регистрации. Основная оболочка изначально `hidden` и `inert`; словарь не запрашивается до проверки сессии. Прямые ссылки и Escape не обходят вход. Сервер требует сессию аккаунта или явно начатого гостевого просмотра для `/api/catalog` и `/api/daily`, иначе отвечает 401 без кеширования. `/health`, оболочка и статические ресурсы доступны до входа.

После регистрации открывается выбор интересов и времени, после повторного входа — сохраненный прогресс. Действующая сессия проходит автоматически. При выходе или подтвержденном истечении сессии сайт снова показывает вход. Ранее вошедшее устройство может продолжать офлайн с локальной копией; после выхода офлайн-доступ закрыт. Новые аккаунты всегда начинают без истории, избранного, скрытых карточек и выбранных интересов. Гостевой импорт удален из регистрации и профиля.

Экран входа поддерживает Noir, Studio и Experimental. Выбор хранится на устройстве в `lexi:entry-theme` и применяется до первого отображения. При переключении введенные данные формы сохраняются; выбранная тема становится начальной темой при регистрации. Вход в существующий аккаунт восстанавливает его тему из базы. Крупные, более контрастные слова декоративные (`aria-hidden`), движутся параллельными потоками из правого верхнего угла в левый нижний под 60° только через CSS transform; полные последовательности слов повторяются без разрыва; есть пауза и автоматическое отключение при reduced motion.

Переключение **Sign in / Create account** плавно меняет высоту карточки, показывает новую форму и перемещает подчеркивание вкладки за 340 мс. При случайном переходе введенные поля обеих форм сохраняются отдельно только в памяти текущего экрана: логин и пароль регистрации не подставляются в форму входа. Закрытие диалога, вход, переход в гостевой режим, смена аккаунта или уход со страницы очищают черновики. В localStorage/sessionStorage и API они не отправляются. Системное или выбранное в LEXI уменьшение движения отключает переход.

## Временный гость

`POST /api/account/guest` с CSRF-токеном создает подписанную непостоянную cookie с `guest_id` и новым CSRF-токеном. Запись пользователя и учебные данные в базе не создаются. Cookie дает доступ только к словарю; прогресс и фото аккаунтов гостю недоступны. Уже вошедший аккаунт должен сначала выйти, сохранив свои изменения.

Гостевой `storage.js` использует только память текущей вкладки. История, избранное, интересы, расписание, оформление и скрытые карточки никогда не записываются в localStorage/sessionStorage, API состояния или кеш Service Worker. Статический словарь и оболочка могут кешироваться. `Exit guest mode` очищает данные немедленно, в том числе офлайн; закрытие, обновление или уход со страницы тоже начинают следующий просмотр с чистого состояния. При офлайн-выходе на сервере временно остается cookie доступа без прогресса; открытая вкладка завершает серверную сессию после подключения. Даже при перезагрузке эта cookie не может восстановить учебные данные.

Вкладки гостя имеют отдельный прогресс. Выход уведомляет другие открытые вкладки через BroadcastChannel без сохранения сообщения в браузерном хранилище. Регистрация создает чистый аккаунт, вход восстанавливает только собственное состояние аккаунта. Импорта гостевых данных нет. Тема экрана входа `lexi:entry-theme` — отдельная настройка интерфейса до гостевого посещения, не учебный прогресс.

## Сессия и API

Сессия Flask подписана, HttpOnly, SameSite=Lax; после входа действует 7 дней. В cookie находятся идентификатор пользователя и CSRF-токен, без email, пароля и прогресса. После регистрации/входа сессия и токен заменяются. API работает только на том же origin; CORS не включен. Все ответы `/api/account/*` имеют `Cache-Control: no-store, private`; Service Worker полностью пропускает эти запросы.

| Метод и путь | Действие |
| --- | --- |
| `GET /api/account/session` | Пользователь, CSRF-токен, учебное состояние и версия |
| `POST /api/account/register` | JSON: `username`, `email`, `password`; сразу входит |
| `POST /api/account/login` | JSON: `identifier` (email/логин), `password` |
| `POST /api/account/guest` | Начинает временный гостевой просмотр без создания пользователя |
| `POST /api/account/logout` | Выход из аккаунта или гостевого просмотра |
| `PUT /api/account/state` | JSON: `state`, `revision`, `progressVersion: 2`; следующая версия или 409 с новым состоянием |
| `GET /api/account/avatar` | Фото текущего пользователя; другим пользователям не доступно |
| `PUT /api/account/avatar` | Multipart-поле `photo` |
| `DELETE /api/account/avatar` | Удаление фото |

Все изменяющие запросы требуют заголовок `X-CSRF-Token` из `/session`. Состояние, фото и выход дополнительно требуют `X-Account-Id`: он должен совпадать с вошедшим пользователем. Гостевой выход вместо него требует `X-Guest-Id`, совпадающий с текущей гостевой cookie; старая вкладка не может завершить другую гостевую сессию или аккаунт. Это исключает запись старой вкладкой в другой аккаунт после смены cookie в соседней вкладке. Чужой идентификатор не дает доступа к чужой записи.

Валидация выполняется на сервере. Фото проверяется по декодированному содержимому, а не расширению: JPEG, PNG, WebP до 5 MB и 16 млн пикселей. EXIF-ориентация применяется, метаданные удаляются, результат уменьшается до 384×384 и сохраняется как JPEG. SVG и произвольные файлы отклоняются. Email не подтверждается, почтовый сервис и восстановление пароля пока не подключены.

## Синхронизация

Старые гостевые данные `lexi:v1` и прежние кеши `:v1` не читаются в учебный профиль. Каждый пользователь использует `lexi:account:<id>:v2`. Это локальные копии учебных данных для офлайн-работы. `lexi:sync:<id>:v2` хранит последнюю серверную версию и признак неотправленных изменений, версию протокола и привязку к идентификатору/дате создания/логину владельца; `lexi:active-account` — только числовой идентификатор. На общем компьютере данные сайта можно очистить средствами браузера после выхода; экспортировать их следует только в личный архив.

После изменения прогресса отправка начинается через 400 мс. При открытии, возвращении во вкладку или восстановлении интернета клиент загружает состояние и объединяет неотправленные изменения с сервером. `revision` проверяется атомарно: устаревшее обновление получает 409 и повторно объединяется. Добавления и удаления в избранном/скрытых словах применяются относительно последней известной версии, история объединяется по паре слово/дата. Независимые изменения настроек сохраняются; для одновременного изменения одного параметра применяется последнее синхронизированное значение. Это не мгновенная совместная работа: открытое второе устройство получает обновление при возвращении во вкладку или перезагрузке.

Выход из аккаунта ожидает отправки изменений; без интернета нужно сначала восстановить соединение. Выход гостя не требует синхронизации и очищает память сразу. Регистрация всегда создает чистый учебный профиль, даже если в браузере остались данные гостя, другого аккаунта или удаленной тестовой базы. При входе объединяются только неотправленные изменения того же владельца. Ответы незавершенных запросов другого аккаунта игнорируются. Сброс учебных данных аккаунта синхронизируется, не удаляя сам профиль и фото.

## Однократная очистка прежних учебных профилей

По запросу владельца проекта `init_database` под той же блокировкой, что защищает создание таблиц, выполняет миграцию `account-progress-isolation-v2`: очищает `users.preferences`, увеличивает `revision` и записывает маркер в `data_migrations`. Она применяется ко всем существующим пользователям один раз. Профиль, email, scrypt-хеш пароля, дата регистрации и фото остаются. На пустой базе записывается маркер до регистрации пользователей. Новые аккаунты и последующие перезапуски не подвергаются повторной очистке. Не удаляйте маркер вручную.

Перед обновлением остановите прежние worker-процессы и сделайте закрытую резервную копию существующей базы. Установите серверную и клиентскую части вместе, затем запустите сервер и обновите страницы. В этом рабочем окружении локальная SQLite была скопирована в игнорируемую `instance/backups/` перед применением; реальные базы на других компьютерах или Render сюда не подключены.

Сервер возвращает `progressVersion: 2` в сессии и требует эту версию при записи состояния. Старый клиент получает 409 `progress_reset` и не может восстановить тестовые данные после очистки. Новые кеши используют отдельное пространство `:v2`; для объединения проверяются владелец, версия протокола и исходная серверная ревизия. При офлайн-обновлении со старой версии сначала нужно войти онлайн. Последующие офлайн-изменения своего аккаунта сохраняются и синхронизируются обычным образом.

## Резервное копирование

- Локально: остановите приложение и скопируйте `instance/` в закрытое место. Восстановите его перед запуском. Не добавляйте эту папку в GitHub и ZIP исходников.
- PostgreSQL: настройте резервное копирование у провайдера и проверьте восстановление. Сохраните `SECRET_KEY` отдельно в менеджере секретов. Перед окончанием срока бесплатной базы перенесите данные в постоянную базу.
- Экспорт в Settings — личный JSON учебного состояния текущего профиля, без пароля и фото; он не заменяет резервную копию базы. Загрузка этого JSON через интерфейс пока не реализована.

ZIP из GitHub содержит исходники, а не реальные аккаунты. Для нескольких устройств нужен общий работающий сервер с постоянной базой.
