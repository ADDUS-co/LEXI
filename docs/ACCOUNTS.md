# Аккаунты LEXI

## Где находятся данные

Словарь остается в `data/*.json`. Личные данные находятся в SQL-базе: таблица `users` хранит уникальные email/логин, scrypt-хеш, фото, учебное состояние и его версию. Таблица `auth_rate_buckets` ограничивает попытки регистрации и входа между worker-процессами. Пароли и сессионные/CSRF-токены не записываются в localStorage.

SQLite создается автоматически в `instance/lexi.sqlite3`. PostgreSQL подключается через `DATABASE_URL` (поддерживаются `postgres://` и `postgresql://`, драйвер psycopg). Таблицы создаются при запуске; одновременный запуск worker-процессов сериализован блокировкой. Проверка подключения: `python -m flask --app app init-db`. Последующие изменения схемы потребуют отдельной миграции: `create_all` не изменяет существующие столбцы.

Локальный постоянный ключ подписи создается в `instance/.session-key`. На сервере задайте постоянный случайный `SECRET_KEY` через Environment, а также `LEXI_COOKIE_SECURE=1` для HTTPS. `LEXI_TRUST_PROXY=1` разрешается только за одним доверенным reverse proxy, как на Render. Без прокси оставьте его выключенным, чтобы адрес клиента для ограничения входа нельзя было подделать через HTTP-заголовок.

## Обязательный вход

Новый посетитель сначала видит отдельный экран регистрации с формой по центру и переключателем трех оформлений. **Sign in** открывает вход для существующего аккаунта. Основная оболочка изначально `hidden` и `inert`; словарь не запрашивается до проверки сессии. Прямые ссылки и Escape не обходят вход. Сервер требует сессию для `/api/catalog` и `/api/daily`, иначе отвечает 401 без кеширования. `/health`, оболочка и статические ресурсы доступны до входа.

После регистрации открывается выбор интересов и времени, после повторного входа — сохраненный прогресс. Действующая сессия проходит автоматически. При выходе или подтвержденном истечении сессии сайт снова показывает вход. Ранее вошедшее устройство может продолжать офлайн с локальной копией; после выхода офлайн-доступ закрыт. Старые гостевые данные сохраняются только для добровольного переноса в аккаунт.

Экран входа поддерживает Noir, Studio и Experimental. Выбор хранится на устройстве в `lexi:entry-theme` и применяется до первого отображения. При переключении введенные данные формы сохраняются; выбранная тема становится начальной темой при регистрации. Вход в существующий аккаунт восстанавливает его тему из базы. Крупные, более контрастные слова декоративные (`aria-hidden`), движутся параллельными потоками из правого верхнего угла в левый нижний под 60° только через CSS transform; полные последовательности слов повторяются без разрыва; есть пауза и автоматическое отключение при reduced motion.

## Сессия и API

Сессия Flask подписана, HttpOnly, SameSite=Lax; после входа действует 7 дней. В cookie находятся идентификатор пользователя и CSRF-токен, без email, пароля и прогресса. После регистрации/входа сессия и токен заменяются. API работает только на том же origin; CORS не включен. Все ответы `/api/account/*` имеют `Cache-Control: no-store, private`; Service Worker полностью пропускает эти запросы.

| Метод и путь | Действие |
| --- | --- |
| `GET /api/account/session` | Пользователь, CSRF-токен, учебное состояние и версия |
| `POST /api/account/register` | JSON: `username`, `email`, `password`; сразу входит |
| `POST /api/account/login` | JSON: `identifier` (email/логин), `password` |
| `POST /api/account/logout` | Выход |
| `PUT /api/account/state` | JSON: `state`, `revision`; следующая версия или 409 с новым состоянием |
| `GET /api/account/avatar` | Фото текущего пользователя; другим пользователям не доступно |
| `PUT /api/account/avatar` | Multipart-поле `photo` |
| `DELETE /api/account/avatar` | Удаление фото |

Все изменяющие запросы требуют заголовок `X-CSRF-Token` из `/session`. Состояние, фото и выход дополнительно требуют `X-Account-Id`: он должен совпадать с вошедшим пользователем. Это исключает запись старой вкладкой в другой аккаунт после смены cookie в соседней вкладке. Чужой идентификатор не дает доступа к чужой записи.

Валидация выполняется на сервере. Фото проверяется по декодированному содержимому, а не расширению: JPEG, PNG, WebP до 5 MB и 16 млн пикселей. EXIF-ориентация применяется, метаданные удаляются, результат уменьшается до 384×384 и сохраняется как JPEG. SVG и произвольные файлы отклоняются. Email не подтверждается, почтовый сервис и восстановление пароля пока не подключены.

## Синхронизация

Старые гостевые данные используют прежний ключ `lexi:v1`; каждый пользователь — `lexi:account:<id>:v1`. Это локальные копии учебных данных для офлайн-работы. `lexi:sync:<id>` хранит последнюю серверную версию и признак неотправленных изменений; `lexi:active-account` — только числовой идентификатор. На общем компьютере данные сайта можно очистить средствами браузера после выхода; экспортировать их следует только в личный архив.

После изменения прогресса отправка начинается через 400 мс. При открытии, возвращении во вкладку или восстановлении интернета клиент загружает состояние и объединяет неотправленные изменения с сервером. `revision` проверяется атомарно: устаревшее обновление получает 409 и повторно объединяется. Добавления и удаления в избранном/скрытых словах применяются относительно последней известной версии, история объединяется по паре слово/дата. Независимые изменения настроек сохраняются; для одновременного изменения одного параметра применяется последнее синхронизированное значение. Это не мгновенная совместная работа: открытое второе устройство получает обновление при возвращении во вкладку или перезагрузке.

Выход ожидает отправки изменений; без интернета нужно сначала восстановить соединение. Новый гостевой просмотр закрыт. При регистрации можно перенести прежний гостевой прогресс; в профиле также доступно объединение гостевых слов с аккаунтом. Перенос не удаляет гостевую копию. Сброс учебных данных аккаунта синхронизируется, не удаляя сам профиль и фото.

## Резервное копирование

- Локально: остановите приложение и скопируйте `instance/` в закрытое место. Восстановите его перед запуском. Не добавляйте эту папку в GitHub и ZIP исходников.
- PostgreSQL: настройте резервное копирование у провайдера и проверьте восстановление. Сохраните `SECRET_KEY` отдельно в менеджере секретов. Перед окончанием срока бесплатной базы перенесите данные в постоянную базу.
- Экспорт в Settings — личный JSON учебного состояния текущего профиля, без пароля и фото; он не заменяет резервную копию базы. Загрузка этого JSON через интерфейс пока не реализована.

ZIP из GitHub содержит исходники, а не реальные аккаунты. Для нескольких устройств нужен общий работающий сервер с постоянной базой.
